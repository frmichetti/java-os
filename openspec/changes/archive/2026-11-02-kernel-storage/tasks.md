# Tasks

## 1. `kernel::pci`: acesso à configuração PCI e enumeração

- [x] 1.1 Adicionar `kernel::port::inl`/`outl` (operações de 32 bits, mesmo padrão de `inb`/`outb` já existentes). Verificar que `cargo kernel-build` compila.
- [x] 1.2 Implementar como função pura a montagem do valor de 32 bits de `CONFIG_ADDRESS` a partir de (barramento, dispositivo, função, offset) — ver design.md. Verificar com teste unitário em host: o bit de habilitação (bit 31) está sempre ligado, e cada campo (barramento, dispositivo, função, offset) aparece nos bits corretos para valores conhecidos.
- [x] 1.3 Implementar `kernel::pci::read_config_dword(bus, device, function, offset) -> u32` (escreve `CONFIG_ADDRESS` via `outl` na porta 0xCF8, lê `CONFIG_DATA` via `inl` na porta 0xCFC) e `kernel::pci::enumerate_bus0() -> impl Iterator<Item = PciDevice>` (varre dispositivo 0-31 × função 0-7, ignora vendor ID `0xFFFF`, devolve posição no barramento, vendor/device ID, classe/subclasse/prog-if, e os 6 BARs). Como depende de portas de I/O reais (não disponível em host), verificar que `cargo kernel-build` compila; a enumeração real é confirmada em boot na tarefa 5.3.

## 2. `kernel::storage`: estruturas AHCI puras (FIS, cabeçalho de comando, PRDT)

- [x] 2.1 Implementar como função pura a montagem dos 20 bytes do FIS de registrador Host-to-Device (ver design.md) para um comando ATA (`READ DMA EXT`/`WRITE DMA EXT`), LBA de 48 bits e contagem de setores. Verificar com testes unitários em host: o tipo do FIS e o bit de comando aparecem nos bytes corretos, o byte de comando corresponde ao parâmetro passado, os bytes de LBA (baixo e alto) correspondem ao valor de 48 bits passado (incluindo um LBA que usa os bits altos), o byte de dispositivo sinaliza modo LBA, e a contagem de setores aparece nos bytes corretos.
- [x] 2.2 Implementar como funções puras a montagem do primeiro dword do cabeçalho de comando (CFL, bit de escrita, contagem de entradas PRDT) e do terceiro dword de uma entrada PRDT (contagem de bytes menos um, bit de interrupção sempre desligado — ver design.md, Non-Goal de E/S por interrupção). Verificar com testes unitários em host: CFL corresponde ao tamanho do FIS em dwords, o bit de escrita reflete a direção passada, PRDTL corresponde à quantidade de entradas passada, e a contagem de bytes da entrada PRDT é o tamanho do buffer menos um.

## 3. `kernel::storage`: driver real (HBA, porta, emissão de comando)

- [x] 3.1 Implementar a inicialização da HBA e da primeira porta implementada com um dispositivo SATA conectado (`PxSIG`/`PxSSTS` — ver design.md): mapear o `ABAR` (BAR5) via `kernel::paging::Mapper` (mesmo tratamento do I/O APIC em `kernel-keyboard` — a HHDM não garante cobri-lo), parar o motor de comando se já estiver rodando, alocar (uma página por estrutura) a lista de comandos, a área de recebimento de FIS e a tabela de comando do slot 0, programar `PxCLB`/`PxFB`/`CTBA`, e ligar o motor de comando (`PxCMD.FRE` e `PxCMD.ST`). Como depende de MMIO real (não disponível em host), verificar que `cargo kernel-build` compila; a inicialização real é confirmada em boot na tarefa 5.3.
- [x] 3.2 Implementar a emissão de um comando no slot 0 (monta o FIS da tarefa 2.1 e o cabeçalho/PRDT da tarefa 2.2 nas estruturas já alocadas pela tarefa 3.1, aponta a entrada PRDT para o buffer do chamador, liga o bit correspondente em `PxCI`, espera — *polling* — até esse bit zerar ou um timeout, verifica erro em `PxTFD`/`PxIS`) usada tanto para leitura quanto escrita. Como depende de MMIO real, verificar que `cargo kernel-build` compila; confirmado em boot na tarefa 5.3.

## 4. `kernel::hal::BlockDevice` e inicialização de alto nível

- [x] 4.1 Adicionar `kernel::hal::BlockDevice` (trait com `block_size`, `read_block`, `write_block`, ver design.md) e o tipo `kernel::storage::AhciDisk` implementando-o por delegação à tarefa 3.2 (leitura = comando `READ DMA EXT`; escrita = `WRITE DMA EXT`). Um `buf` de tamanho diferente de `block_size()` é um erro explícito (`BlockError`), nunca uma operação parcial silenciosa — verificar com teste unitário em host cobrindo essa validação (lógica pura, sem tocar hardware).
- [x] 4.2 Implementar `kernel::storage::init(frame_allocator) -> Result<(), StorageError>`: usa `kernel::pci::enumerate_bus0` para localizar o controlador AHCI (classe 0x01, subclasse 0x06, interface de programação 0x01), inicializa a HBA/porta (tarefa 3.1), e guarda o `AhciDisk` resultante num global atrás de `Spinlock` (mesmo padrão de `kernel::framebuffer::CONSOLE`/`kernel::keyboard`). Trata explicitamente, sem travar o boot, a ausência de um controlador AHCI ou de um dispositivo SATA em nenhuma porta — mesmo espírito de "indisponibilidade tratada explicitamente" já usado em `kernel-framebuffer-console`. Verificar que `cargo kernel-build` compila.

## 5. Integração: demonstração, inicialização em `kernel_main` e verificação de ponta a ponta

- [x] 5.1 Implementar `kernel::storage_demo::run()` (não uma thread em loop como `keyboard_demo` — é uma operação única, não um fluxo contínuo de eventos): lê o primeiro setor (LBA 0) do disco já inicializado, confirma a assinatura de inicialização `0x55AA` nos dois últimos bytes, e reporta o resultado via `serial_println!`. Só leitura — não escreve no disco de boot (ver tarefa 5.3 para a verificação de escrita, feita manualmente num LBA seguro). Verificar que `cargo kernel-build` compila.
- [x] 5.2 Em `continue_boot` (`kernel/src/main.rs`), depois do escalonador e do I/O APIC já estarem prontos: chamar `kernel::storage::init(&mut frame_allocator)` e, se bem-sucedido, `kernel::storage_demo::run()`; se `init` falhar (sem controlador AHCI ou sem disco), reportar pelo console serial e prosseguir o boot normalmente, sem travar. Verificar com `cargo xtask test` que o boot continua passando sem regressão no console serial (o smoke test já roda sobre a mesma imagem de disco de boot servida via AHCI pelo QEMU/Q35 — ver design.md).
- [x] 5.3 Validar em boot real (QEMU) que a demonstração da tarefa 5.1 lê corretamente o primeiro setor do disco de boot e reporta a assinatura `0x55AA`. Validar também, manualmente (fora do fluxo de boot automático, para não arriscar a imagem usada por todo o resto do projeto), uma escrita seguida de leitura num LBA seguro (bem fora da área usada pela partição EFI/kernel — escolher e documentar aqui qual LBA foi usado) confirmando que o conteúdo escrito é exatamente o lido de volta. **Se a enumeração PCI não encontrar o controlador AHCI, ou a porta não detectar o dispositivo SATA**, investigar antes de prosseguir (candidatos mais prováveis: barramento/dispositivo/função errados para o chipset do QEMU em uso, ABAR mal mapeado, ou necessidade de habilitar `GHC.AE` explicitamente — ver design.md) e documentar o achado real em design.md, como já é costume neste projeto.
