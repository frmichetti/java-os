## 4. `kernel::syscall`: ABI, despacho e as duas primeiras chamadas

- [x] 4.1 Definir a convenção de ABI (número em `RAX`, argumentos em `RDI`/`RSI`/`RDX`/`R10`, retorno em `RAX`) e os números das duas chamadas (`WRITE = 0`, `GET_TICKS = 1`). Implementar o despacho (`dispatch(number, arg0, arg1, ...) -> u64`) como função Rust pura o suficiente para testar em host (sem tocar hardware diretamente no corpo do despacho) e verificar com teste unitário que um número de chamada desconhecido devolve o valor de erro sentinela (`u64::MAX`) em vez de executar qualquer serviço.
- [x] 4.2 Implementar a chamada de escrita (`sys_write(ptr, len)`, escreve byte a byte via `SerialPort::write_byte`, agora `pub`) e a chamada de consulta de ticks (`sys_get_ticks`, devolve `kernel::timer::ticks()`). Como `sys_write` toca `outb` (I/O privilegiado, mesma classe de limitação de `CR3`/HHDM já documentada alhures), verificado com teste unitário em host apenas `GET_TICKS` (compara com `kernel::timer::ticks()` real) e o número desconhecido (tarefa 4.1); `SYSCALL_WRITE` é verificado em boot real na tarefa 6.1.
- [x] 4.3 Escrever `syscall_entry` (assembly puro, `global_asm!`, mesmo padrão de `scheduler::timer_entry`): salva `RSP` de usuário em `SYSCALL_USER_RSP_SCRATCH`, troca para `CURRENT_KERNEL_STACK_TOP` (nova variável `#[no_mangle]` em `scheduler.rs`, atualizada no mesmo ponto que `TSS.rsp0` via uma função central `set_current_kernel_stack` — ver design.md, mitigação do risco de divergência entre as duas), salva RCX/R11 (RIP/RFLAGS do usuário), reorganiza os registradores da convenção desta syscall para a convenção System V de `dispatch` (agora `extern "C"` + `#[no_mangle]`), restaura RCX/R11 e o RSP de usuário, retorna via `sysretq`. `syscall::init()` (chamada em `continue_boot`, depois da thread de boot registrada) aponta `LSTAR` para ela. Verificado que `cargo build`/`cargo kernel-build` compilam e que o cross-reference de símbolos entre `scheduler.rs`/`syscall.rs` linka corretamente; `cargo xtask test` confirma boot completo sem regressão, com a nova linha "syscall/sysret: configurado" no log. A troca de privilégio real é verificada em boot na tarefa 6.1.

## 5. Programa de teste em modo usuário

- [x] 5.1 Escrever (`kernel/src/user_demo.rs`), via `core::arch::global_asm!`, uma rotina de teste independente de posição que chama a syscall de escrita com uma mensagem fixa, chama a syscall de consulta de ticks, e repete em laço — com rótulos de início/fim para permitir copiar seus bytes. **Achado durante a implementação:** o assembler não aceita subtração de dois símbolos (`4f - 3f`) direto como operando imediato de `mov`; corrigido armazenando o tamanho da mensagem como dado (`msglen: .long 4f - 3f`) e carregando via `mov esi, [rip + msglen]`. Verificado que `cargo build`/`cargo kernel-build` compilam.
- [x] 5.2 Implementado `scheduler::spawn_user_demo` (cria o processo de demonstração via `Process::begin_new_user`/`finish_new_user`, mapeia a página de código, copia os bytes da tarefa 5.1, cria a thread de usuário, registra no escalonador), chamado em `continue_boot`. **Três bugs reais encontrados e corrigidos em boot real antes da verificação passar (ver design.md — "Primeiro programa de usuário", achados 1-3):**
  1. Cópia dos bytes do programa direto em `USER_DEMO_CODE_VIRT` falhava (página só mapeada na PML4 inativa do novo processo) — corrigido copiando via o alias HHDM do frame.
  2. Nada trocava `CR3` entre processos na troca de contexto — corrigido adicionando `address_space_root` ao `Context` e chamando `paging::switch_address_space` em todo `on_timer_tick`.
  3. Mesmo com (1) e (2) corrigidos, a própria stack de kernel da thread de usuário ficava inacessível após a troca de `CR3` — `AddressSpace::new()` copia a PML4 por valor, e o índice do pool de stacks de thread ainda não existia na PML4 ativa no momento da cópia. Corrigido com `kernel::stack::prime_thread_stack_pool`, chamada uma vez antes de qualquer `AddressSpace::new()`.

  Verificado com `cargo xtask test`: o log serial mostra a mensagem "ola do modo usuario, via syscall!" repetida continuamente, vinda do processo de modo usuário sobrevivendo a múltiplas preempções do timer — prova round-trip completo de `syscall`/`sysret` em anel 3. `cargo test -p kernel --lib` confirmado em 54/54.
