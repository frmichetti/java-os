# Tasks

## 1. `kernel::gpt`: parsing puro de GPT + localização da partição EFI

- [x] 1.1 Implementar `GptHeader::parse(buf: &[u8; 512]) -> Option<GptHeader>` (valida a assinatura `"EFI PART"`, extrai `partition_entry_lba`/`num_partition_entries`/`size_of_partition_entry`) e `GptPartitionEntry::parse(buf: &[u8]) -> GptPartitionEntry` (extrai `partition_type_guid`/`starting_lba`). Verificar com testes unitários em host: um cabeçalho GPT válido (bytes conhecidos) é parseado corretamente; um buffer sem a assinatura correta devolve `None`; uma entrada de partição com o GUID e o LBA inicial conhecidos é extraída corretamente.
- [x] 1.2 Implementar a constante `EFI_SYSTEM_PARTITION_GUID` e confirmar, por teste unitário em host, que seus 16 bytes correspondem à codificação mista correta do GUID `C12A7328-F81F-11D2-BA4B-00A0C93EC93B` (primeiros três campos *little-endian*, últimos dois como escritos).
- [x] 1.3 Implementar `find_efi_system_partition<D: hal::BlockDevice>(device: &mut D) -> Result<u64, GptError>`, genérica sobre `hal::BlockDevice` (ver design.md). Criar um `BlockDevice` simulado por um buffer em memória (mesmo papel de `kernel::phys::tests::SimulatedFrameStore`) para os testes. Verificar com testes unitários em host: um disco simulado com uma tabela GPT válida contendo uma partição do tipo EFI System devolve seu `starting_lba` correto; um disco sem cabeçalho GPT válido devolve `GptError::NoGptHeader`; um disco com GPT válido mas sem nenhuma partição EFI System devolve `GptError::NoEfiSystemPartition` — cobre "Nenhuma partição FAT32/EFI é encontrada" da spec `kernel-filesystem`.

## 2. `kernel::fat32`: parsing puro de BPB, entradas de diretório e FAT

- [x] 2.1 Implementar `Bpb::parse(buf: &[u8; 512]) -> Result<Bpb, Fat32Error>` com os métodos derivados `first_fat_sector()`, `first_data_sector()`, `cluster_to_sector(cluster)`, `fat_entry_location(cluster)`. Verificar com testes unitários em host: um setor de inicialização FAT32 válido (bytes conhecidos, assinatura `0x55AA` e `"FAT32   "`) é parseado corretamente, com os valores derivados batendo com cálculo manual para um caso conhecido; um buffer sem a assinatura de inicialização, ou sem `"FAT32   "` no campo de tipo de sistema de arquivos, é rejeitado explicitamente — cobre "Partição encontrada não é um FAT32 válido" da spec.
- [x] 2.2 Implementar `DirEntry::parse(buf: &[u8; 32]) -> DirEntryKind` (`EndOfDirectory`/`Free`/`LongNamePart`/`Entry`). Verificar com testes unitários em host: uma entrada de arquivo válida decodifica nome curto (8.3, *trim* de espaços), atributo de diretório vs. arquivo, cluster inicial (`FstClusHI:FstClusLO` combinados) e tamanho corretamente; o primeiro byte `0x00` devolve `EndOfDirectory`; o primeiro byte `0xE5` devolve `Free`; o atributo `0x0F` devolve `LongNamePart`.
- [x] 2.3 Implementar `fat_entry_value(raw: u32) -> u32` (máscara dos 4 bits altos) e `is_end_of_chain(value: u32) -> bool`. Verificar com testes unitários em host: um valor bruto com os 4 bits altos "sujos" é mascarado corretamente; valores `>= 0x0FFF_FFF8` são reconhecidos como fim de cadeia; um valor de cluster normal não é.
- [x] 2.4 Implementar `short_name_matches(entry_name: &str, component: &str) -> bool` (comparação *case-insensitive*). Verificar com testes unitários em host: `"KERNEL"` bate com `"kernel"`; `"BOOTX64.EFI"` bate com `"bootx64.efi"`; nomes diferentes não batem — cobre "Correspondência de Nomes Curtos Sem Distinção de Maiúsculas/Minúsculas" da spec.

## 3. `kernel::fat32`: montagem e leitura de arquivo (camada real, genérica sobre `BlockDevice`)

- [x] 3.1 Implementar `Fat32Filesystem::mount<D: hal::BlockDevice>(device: &mut D, partition_start_lba: u64) -> Result<Self, Fat32Error>`, validando `bpb.bytes_per_sector == device.block_size()` (`Fat32Error::UnsupportedSectorSize` caso contrário). Construir, para os testes, uma pequena partição FAT32 sintética completa em memória (setor de inicialização + FAT + diretório raiz com algumas entradas + dados de arquivo) por trás do `BlockDevice` simulado da tarefa 1.3. Verificar com testes unitários em host: montar a partição sintética válida tem sucesso; montar um setor de inicialização inválido (da tarefa 2.1) devolve erro; `bytes_per_sector` diferente de `device.block_size()` é rejeitado.
- [x] 3.2 Implementar `Fat32Filesystem::read_file<D: hal::BlockDevice>(&self, device: &mut D, path: &str) -> Result<Vec<u8>, Fat32Error>`, incluindo a função interna de resolução de diretório e a leitura da cadeia de clusters do arquivo via a FAT. Na partição sintética da tarefa 3.1, incluir pelo menos um arquivo cujo conteúdo ocupe mais de um cluster (clusters não necessariamente consecutivos na FAT). Verificar com testes unitários em host: ler um arquivo de um único cluster devolve seu conteúdo exato; ler o arquivo multi-cluster devolve todo o conteúdo, na ordem correta, batendo com o tamanho declarado — cobre "Leitura de um arquivo existente devolve seu conteúdo completo e correto" (incluindo multi-cluster) da spec.
- [x] 3.3 Cobrir os caminhos de erro de `read_file` com testes unitários em host, usando a mesma partição sintética: caminho para um arquivo/diretório inexistente devolve erro; caminho cujo componente final é um diretório devolve erro; caminho cujo componente intermediário é um arquivo (não diretório) devolve erro — cobrem, respectivamente, "Caminho não corresponde a nenhum arquivo ou diretório existente", "Caminho aponta para um diretório, não um arquivo" e "Um componente intermediário do caminho não é um diretório" da spec.
