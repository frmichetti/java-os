Host e alvo são ambos x86_64 — ver design.md, "Wrapper fino sobre o GCC do host": não é necessário compilar um binutils+GCC dedicado, só um wrapper fino sobre as ferramentas de host já instaladas (`gcc`, `ar`, `ranlib`).

- [x] 2.1 Criar um script wrapper versionado (`scripts/cross/x86_64-elf-gcc`) que invoca o `gcc` do host com `-ffreestanding -nostdlib -fno-pie -no-pie -fno-stack-protector` e as flags de sem-SSE (`-mno-sse -mno-sse2 -mno-sse3 -mno-mmx -mno-80387`), replicando as features do target Rust `x86_64-java_os_user.json`; wrappers triviais análogos `scripts/cross/x86_64-elf-ar`/`x86_64-elf-ranlib` sobre `ar`/`ranlib` do host (`-msoft-float` deliberadamente omitido do wrapper em si — ver achado da tarefa 2.3/design.md: não existe soft-float utilizável em x86_64 sem SSE, então essa flag teria efeito nenhum além de alertar sobre algo que já é tratado configurando o newlib sem ponto flutuante, tarefa 3.7)
- [x] 2.2 Colocar o diretório desses wrappers no `PATH` (documentado no README, mesmo padrão das demais ferramentas de host já exigidas) para que o sistema de build do newlib os encontre pela convenção de triplo
- [x] 2.3 Verificar que `x86_64-elf-gcc` compila e linka um `.c` trivial freestanding (sem usar nenhuma função de libc) para um ELF64 x86_64 válido, confirmado via `readelf -h`/`file` — **achado real durante esta tarefa**: compilar uma função retornando `double` falha com `error: SSE register return with SSE disabled` — documentado em design.md e propagado como Non-Goal (proposal.md)
- [x] 2.4 Verificar, via `objdump -d` do binário gerado na tarefa 2.3, que nenhuma instrução SSE/x87 aparece no código gerado (confirma que as flags da tarefa 2.1 realmente têm efeito)

## 3. Newlib vendorizado e stubs de retarget

**Achado durante a implementação** (inspecionando o código-fonte vendorizado — ver design.md): o newlib **não precisa** de um `libc/sys/javaos` dentro da sua própria árvore. Para um triplo sem correspondência conhecida (`x86_64-elf`), `configure.host` builda só a camada genérica (`libc/syscalls`/`libc/reent`), que já deixa `_read`/`_write`/`_open`/`_close`/`_lseek`/`_sbrk`/`_fstat`/`_isatty`/`_exit`/`_kill`/`_getpid` como símbolos indefinidos em `libc.a`, resolvidos por um arquivo nosso fora da árvore do newlib, linkado junto no final de cada programa.

- [x] 3.1 Vendorizar o código-fonte do newlib localmente (`newlib-4.6.0.20260123`, versão estável mais recente disponível em `sourceware.org/pub/newlib/` no momento da implementação — documentada no README, não versionada no Git — adicionar `vendor/` ao `.gitignore`, mesmo tratamento de `boot/limine`)
- [x] 3.2 Configurar e compilar o newlib **genérico** (`--target=x86_64-elf`, sem `sys_dir` — ver achado acima) com o wrapper da tarefa 2; **achado real durante esta tarefa** (ver design.md, "Segundo achado"): `--disable-newlib-io-float` sozinho não basta — `libm` inteira e ~17 arquivos de `libc/stdlib`/`libc/time` (conversão float/`difftime`) ainda são tentados e falham sob `-mno-sse`, impedindo o `make all` padrão de arquivar `libc.a`. Resolvido com `make -k` (script `scripts/cross/build-newlib.sh`) seguido de arquivamento manual (`x86_64-elf-ar`) só dos 586 objetos de `libc/` que realmente compilaram — `libc.a` de 6.3 MiB gerado com sucesso, cobrindo `stdio`/`string`/`reent`/`signal`/`errno`/`misc`/`locale`/`ssp`/`machine/x86_64` por completo
- [x] 3.3 Escrever, fora da árvore do newlib (`userland_c/glue.c`), o arquivo de glue com `_read`/`_write`/`_open`/`_close` traduzindo diretamente para `SYSCALL_READ`/`SYSCALL_WRITE`/`SYSCALL_OPEN`/`SYSCALL_CLOSE` já existentes, e `_lseek` devolvendo erro (`ESPIPE`, já que as syscalls de arquivo atuais só avançam cursor por leitura sequencial — ver spec `kernel-filesystem`). **Achado durante a implementação**: descritores 0/1/2 (stdin/stdout/stderr, que o newlib já assume) colidiriam com os handles de `kernel::file_handles` (que também numeram a partir de 0) — resolvido com um offset fixo (`FD_OFFSET = 3`) aplicado em `_open`/`_read`/`_close`, nunca exposto fora do glue
- [x] 3.4 Implementar `_sbrk` no mesmo arquivo de glue: reserva uma janela de heap de tamanho fixo (16 MiB) uma única vez via `SYSCALL_VM_RESERVE` na inicialização do processo, e cada chamada comete via `SYSCALL_VM_COMMIT` só as páginas adicionais necessárias para cobrir o novo cursor de break, devolvendo erro (`ENOMEM`) se a janela reservada se esgotar
- [x] 3.5 Implementar `_fstat` (relato mínimo: trata todo descritor válido como dispositivo de caractere) e `_isatty` (sempre `1` para os descritores padrão, já que não há um driver de terminal real)
- [x] 3.6 Implementar `_exit`/`_kill`/`_getpid` sobre a nova `SYSCALL_EXIT` (`_exit` invoca a syscall e nunca retorna; `_kill`/`_getpid` são stubs mínimos suficientes para o newlib linkar, já que não há sinais nem PIDs reais ainda)
- [x] 3.7 Escrever um `crt0` mínimo (`userland_c/crt0.S`: chama `main()`, chama `_exit` com o valor de retorno — `.bss` já é zerado pelo carregador do kernel, mesma garantia já coberta pela spec `kernel-elf-loader`, confirmada em boot real por `elf_test_program`) e verificar que o arquivo de glue + `crt0` compilam com o wrapper da tarefa 2 sem erro. **Achado durante a implementação**: um comentário citando o caminho da change com um glob (`archive/*/libc-minimal-port`) continha a sequência `*/`, fechando o comentário C prematuramente e quebrando a compilação — corrigido removendo o glob da prosa dos comentários
